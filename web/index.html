Chế độ LLM thuần - chỉ dùng để demo

Mọi lớp bên dưới bị bỏ qua: định tuyến, guardrail, truy xuất, che dữ liệu cá nhân, kiểm tra dẫn nguồn. Đây là model trả lời chỉ dựa trên lịch sử hội thoại - chính là mốc so sánh mà phần còn lại của kiến trúc sinh ra để vượt qua.

Trợ lý chỉ trả lời dựa trên tài liệu đã được ngân hàng thẩm định. Không bao giờ cung cấp mã OTP, mã PIN hay số thẻ đầy đủ cho bất kỳ ai.

Nguồn câu trả lời

Câu trả lời vừa rồi dựa trên đâu. Kỹ thuật chi tiết - định tuyến, độ tin cậy, đường ra quyết định - đã chuyển sang màn hình nhân viên, nơi người đọc chúng thực sự làm việc.

Gửi một câu hỏi để xem nguồn.

Đăng nhập

Màn hình khách không cần đăng nhập. Trang này dành cho nhân viên trung tâm dịch vụ khách hàng.

Tài khoản demo: agent / demo1234.

Cơ chế phân quyền

Every staff endpoint checks the session server-side before doing any work. Hiding a screen in JavaScript is not a control - the routes answer anyone who calls them directly, so the check lives in the handler.

Demo-grade: the account is PBKDF2-hashed in source, sessions are in memory and clear on restart, and the cookie is HttpOnly + SameSite=Lax but not Secure because this runs over plain HTTP on localhost. A real deployment authenticates against the bank's identity provider.

About key handling

            
A key entered here is held in this process's memory only - never
              written to disk, and no endpoint returns it. The catalogue shows a
              mask (sk-a…4f2c), never the value.

            
It is still plaintext in the process environment. Fine for a demo,
              not how to handle credentials in production.
