About key handling

        
A key entered here is held in this process's memory only - never written
          to disk, and no endpoint returns it. The catalogue shows a mask
          (sk-a…4f2c), never the value.

        
It is still plaintext in the process environment, readable by anything
          that can read the process. The server also binds to localhost with no
          authentication. That is fine for a demo and is not how to handle
          credentials in production, where they belong in a secrets manager read
          at start-up with no UI path to set them.
